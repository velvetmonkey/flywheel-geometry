# Crucible — system overview

The personal task / decision tracking system I've been building on weekends. Half because I needed it; half because building it teaches me more about distributed systems than reading would. Started in late 2024.

**What it does**: stores tasks, decisions, and evidence as a graph. Each task can carry one or more *assumptions* (things that need to be true for it to succeed); each assumption has a falsifier and a resolution event. The graph evolves as outcomes come in, propagating updates to dependent tasks. Local-first storage, optional sync to a personal server.

**Architecture**:
- **Storage**: SQLite with a small set of carefully-chosen tables. Tasks, assumptions, evidence events, and a graph edge table. Indexed for the queries I actually run.
- **Sync**: CRDT-based merging via `automerge`. Operates in the background; conflicts are rare because most edits are append-only.
- **CLI**: TypeScript. Single binary, no install dance. The CLI is the primary interface; the web UI is an afterthought.
- **Web UI**: lightweight React app, runs locally. Used for browsing, not entry.

**What I learned from building it**:
- Idempotency is the universal solvent. Every operation is structured so retrying it has no side effects. This made the sync layer about 100× simpler than designing it the first time without that constraint. Retrofitting idempotency later is hell.
- SQLite is genuinely enough for personal-scale data. The hours I'd have spent making Postgres work nicely were spent on actual product instead.
- The graph queries are where the value lives. Tasks-and-assumptions in isolation are a mediocre todo list. Tasks-and-assumptions *with their dependencies tracked* lets me see when an upstream falsifier resolves which downstream tasks become moot.

**Current limitations**:
- The CRDT merge handles 95% of cases beautifully and the remaining 5% require manual resolution. Acceptable for personal use; would not survive multi-user.
- No true multi-device offline. The sync is fine when devices are online; gets confused when one's been offline for a month.
- No real backup story. The local SQLite file is the source of truth; if I lose the laptop, I lose the data. Need to plug in a backup pipeline before scaling up.

**Why the geodesic-retrieval project matters for Crucible**: if the retrieval method works, Crucible's "find related tasks" feature gets dramatically more useful. Right now it's text-search-based and misses cross-domain connections (the same kind I notice when journaling).
